`DatePicker` is the form component used to capture a date (and, optionally, a time) through
a floating calendar built on top of `Input`. It reuses `Input`'s color, variant, size, and
border radius options so it can be dropped into the same forms as `Input` without breaking
visual consistency, while adding its own calendar/clock panel, locale support, and footer
actions.

> **Note:** All examples below are live — you can use Storybook's Controls panel to change
> props and instantly test the component's behavior.

---

## Variant

`DatePicker` offers the same visual variants as `Input`, each carrying a different level of
emphasis. Variants with a stronger border stand out more clearly in standard forms, while
softer, borderless options blend into the surrounding interface and work well for embedded
or low-emphasis contexts. For consistency in your design language, it's recommended to use a
single variant within the same form, including any `DatePicker` fields placed alongside
regular `Input` fields.

## Color

The component supports the same wide range of color options as `Input` so it can align with

and success.

## Disabled

When the `disabled` prop is set to `true`, the field is closed off to user interaction, the
calendar can no longer be opened, and the input is visually dimmed with the cursor switching
to `not-allowed`. This state is used for read-only data, permission restrictions, or date
fields waiting for a previous step to be completed.

<Canvas of={DatePickerStories.Disabled} />

## Border Radius

Corner rounding can be customized across the same range of options available on `Input` and
is an important visual variable that determines the overall "hard/soft" feel of your design
system. For consistency across the project, it's generally recommended to use a single
border radius value across all forms.

<Canvas of={DatePickerStories.Radius} />

## Size

The component offers the same height options as `Input`. Smaller sizes are preferred for
compact contexts like in-table editing, mid-range sizes serve as the default for standard
forms, and larger sizes are used on mobile or for fields that need to stand out and draw
attention.

<Canvas of={DatePickerStories.Size} />

## Validation

Displays validation feedback such as error or success states. Useful for required date
fields or form validation scenarios where a date must be selected before continuing.

<Canvas of={DatePickerStories.Validation} />

## Clock (Date & Time)

When the `config.isClock` option is enabled, a clock panel is rendered next to the calendar,
letting the user pick an hour and a minute in addition to a date. The underlying input
switches from `date` to `datetime-local` accordingly. This is used whenever an exact moment
in time — not just a day — needs to be captured, such as an appointment slot or a scheduled
event.

<Canvas of={DatePickerStories.WithClock} />

## Footer Button

When the `config.isFooterButton` option is enabled, a footer with "Now" and "Okay" actions
is rendered beneath the calendar (and the clock panel, when also enabled). "Now" immediately
jumps the selection to the current date and time, while "Okay" confirms the currently
highlighted selection and closes the calendar. This is useful when users need an explicit
confirmation step rather than relying solely on clicking a day or a time cell.

<Canvas of={DatePickerStories.FooterButton} />

## Locale

`DatePicker` translates weekday names, month names, and its action button labels based on
the `config.locale` option. The example below places a Turkish (`tr`) and an English (`en`)
instance side by side so the difference in labels is directly comparable. This is useful for
multi-language products where the same form needs to render correctly regardless of the
active locale.
